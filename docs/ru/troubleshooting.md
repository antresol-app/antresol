# Решение проблем

Сначала посмотрите журнал сервера — почти всегда причина там:

```sh
docker compose logs --tail 100 antresol
```

## Сервер не видит файлы

- В `.env` путь хоста бывает только в `MEDIA_DIR`. Переменные `VAULT_*_DIR` — пути внутри
  контейнера, они начинаются с `/media`. Ошибки `stat ...: no such file or directory` и
  `mkdir ...: permission denied` обычно означают путь хоста в `VAULT_*`.
- Проверьте папки: **Настройки → Сервер → Медиатека → Папки на сервере**.
- Новые файлы появляются в течение 15 минут. Чтобы сразу: **Пересканировать медиатеку**.

## Нет прав на запись

Контейнер работает от пользователя с uid 1000. Если файлы принадлежат другому пользователю:

- дайте uid 1000 право записи в медиа-папку, или
- добавьте сервису `antresol` в `compose.yml` строку `user: "<uid>:<gid>"` владельца файлов.

Точную команду показывает **Настройки → Сервер → Состояние → Папки** (и **Медиатека → Папки на
сервере → Проверить**).

## Приложения не видят сервер

Приложения ищут сервер в домашней сети по mDNS (`antresol.local`) и UDP на порту 8420.

- Телефон и сервер должны быть в одной сети (не гостевой Wi-Fi).
- Сервис `antresol-mdns` из `compose.yml` должен работать: `docker compose ps`.
- **Docker Desktop (macOS, Windows), WSL 2, Podman machine:** контейнеры там в виртуальной
  машине, автоматический поиск не работает. Введите в приложении `http://<IP компьютера>:8420`.
- Android до 12-й версии не понимает имена `.local`: используйте IP.

Какое имя занял сервер, видно в **Настройки → Мои настройки → О сервере**.

## Два сервера на одном компьютере

Второй стек — в своей папке, со своими `container_name` и строкой `HTTP_PORT=8421` в `.env`.
Он откроется по `http://antresol.local:8421`. Приложения найдут его по mDNS.

## Вход без пароля не работает вне дома

Так и задумано: профиль без пароля входит только из домашней сети. Поставьте пароль:
**Настройки → Сервер → Профили → Изменить**.

Если не пускает и дома, а сервер стоит за прокси — см. следующий пункт.

## В журнале «does not list it»

```
request from 172.18.0.1 carries X-Forwarded-For ... VAULT_TRUSTED_PROXIES does not list it
```

Запросы идут через обратный прокси, о котором сервер не знает. Впишите этот адрес в
`VAULT_TRUSTED_PROXIES` в `.env` и выполните `docker compose up -d`.
Подробно — [Публичный адрес](public-address.html).

## «Адрес возврата строится из внешнего адреса сервера, а он ещё не задан»

Не задан внешний адрес. Впишите его в **Настройки → Сервер → Адрес сервера**. См.
[Публичный адрес](public-address.html).

## Нет франшиз из разных коллекций, рейтингов, текстов песен или пропуска заставок

Это дают открытые сервисы, и на вашем сервере они могут быть выключены. Загляните в **Настройки →
Сервер → Внешние сервисы**: Wikidata объединяет франшизы и даёт оценки Rotten Tomatoes, рейтинги
IMDb и тексты песен (LRCLIB) выключены, пока вы их не включите, TheIntroDB и IntroDB отмечают
заставки и титры. Переключатель с пометкой «на сервере» задан переменной в `.env`: см.
[Внешние сервисы](configuration.html#external-services). После включения Wikidata франшизы
пересчитываются за несколько минут.

## Расширение пишет «служба не найдена»

Расширению нужна вспомогательная служба в `compose.yml`. См.
[Вспомогательные службы](addon-services.html).

## Видео тормозит или не перекодируется на видеокарте

Проверьте **Настройки → Сервер → Состояние → Оборудование** или **Обработка**: там видно, нашлась
ли видеокарта. Как её подключить — [Перекодирование на видеокарте](hardware-transcoding.html).

## Не нашли ответ

Откройте [issue на GitHub](https://github.com/antresol-app/antresol/issues) и приложите
последние строки журнала.
